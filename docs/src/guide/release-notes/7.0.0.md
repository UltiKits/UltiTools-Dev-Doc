# UltiTools-API 7.0.0 Release Notes

7.0.0 is a breaking release. The framework now targets Paper 26.3 (build 258) with Java 25, admits only modules whose root `plugin.yml` declares an integer `api-version` of `700` or higher, and removes many 6.x public APIs. A module JAR that declares no valid `api-version` or a level below `700` is refused at start-up. Changing only the declaration of a 6.x JAR lets it pass this check, but it can still fail while loading or when it calls a removed API: migrate each module's source, rebuild it against 7.0 and install the rebuilt JAR. Start with [Upgrading from 6.x to 7.0](/guide/advanced/upgrading-to-7).

7.0.0 replaces the command, text, scheduling, item and screen systems with implementations built on Paper and Adventure. It also adds a bootstrap phase for custom content and queues module installs, updates and uninstalls until the next restart. 7.0.0 is a new public API baseline and is not checked for compatibility with 6.x.

The full list for module authors is in [COMPATIBILITY.md][compatibility policy]. The release page is [v7.0.0 on GitHub](https://github.com/UltiKits/UltiTools-Reborn/releases/tag/v7.0.0).

::: warning 6.x module JARs need a rebuild
UltiTools 7.0 refuses a module whose `plugin.yml` declares no valid `api-version` or a level below `700`. Passing this check does not make a 6.x JAR compatible: migrate and rebuild every module as the upgrade guide describes, and back up the server first.
:::

## Before Upgrading

- Back up the old framework and module JARs, configuration, worlds and module data. Items written by 7.0 cannot be read by 6.x, and a downgrade in place is not supported; to return to 6.x, restore the backup.
- Let every pending 6.x `/upm update` finish one confirming start on 6.x before you install 7.0.
- Install Java 25 and Paper 26.3 build 258. At start-up Paper resolves the framework's runtime libraries, so the server needs access to Maven Central or to the mirror set in Paper's `PAPER_DEFAULT_CENTRAL_REPOSITORY` environment variable, unless the libraries are already cached.
- Obtain a 7.0 build of every module you run. Operator edits in old `lang/` files are not carried over; move them into message override files as described in [Messages and Languages](/guide/essentials/messages).

See [Before you upgrade](/guide/advanced/upgrading-to-7#before-upgrade) for the full steps.

## Runtime Requirements

As of v7.0.0, the target is Paper 26.3 (build 258) with Java 25. Older Paper versions and plain Spigot are not supported targets; see [Older Servers](/guide/advanced/older-servers) for the historical 6.x guidance. ([#928](https://github.com/UltiKits/UltiTools-Reborn/pull/928))

The framework JAR is now a Paper plugin: it contains `paper-plugin.yml` instead of `plugin.yml`. Module JARs keep their own `plugin.yml`. If Paper cannot download a runtime library, it may report only `Error resolving libraries`; check the server's network access and the mirror. ([#951](https://github.com/UltiKits/UltiTools-Reborn/pull/951))

## Module Admission

As of v7.0.0, a module's root `plugin.yml` must declare an integer `api-version` from `700` through the running framework's API level. Rebuild 6.x modules against 7.0 and the target Paper version; changing the declaration alone does not make a 6.x JAR compatible. See [Build target and module admission](/guide/advanced/upgrading-to-7#build-target).

The framework loads admitted module JARs unchanged. The 6.x load-time bytecode adaptation, server API probing and start-up and offline linkage audits are removed. ([#937](https://github.com/UltiKits/UltiTools-Reborn/pull/937))

## Commands

As of v7.0.0, UltiTools compiles annotation-based commands into Brigadier trees and registers them through Paper's command lifecycle event. It no longer registers them by editing Bukkit's private command map. A command format that 6.x accepted can now prevent its module from loading; see [Command Executor](/guide/essentials/cmd-executor) and its [rejected formats](/guide/essentials/cmd-executor#rejected-formats). ([#965](https://github.com/UltiKits/UltiTools-Reborn/pull/965))

- With `language: auto` in the framework's `config.yml`, the default, framework replies to commands, such as usage, permission refusals and cooldown notices, use each player's client language, and non-player senders get `fallback-language`. A concrete `language` value is used for every player instead. ([#977](https://github.com/UltiKits/UltiTools-Reborn/pull/977))
- `@AsyncCommand(processingMessageKey = ...)` takes a message key in `<namespace>:<path>` form. An invalid value logs one warning and the default processing message is used.
- Asynchronous command bodies run on the framework scheduler. When one module is unloaded while the server runs, the framework waits up to about 10 seconds in total for that module's running asynchronous commands, without interrupting them. At server stop, the command executors of the framework and all modules share one allowance: once earlier executors have used it up, later ones do not wait, and commands that have already started may keep running.

## Text and Languages

As of v7.0.0, `Messages` and the `messages/<locale>.yml` catalogues are the only text system. Each player receives text in their own client language, subject to the operator's language settings. Module configuration comments, command descriptions and hints also come from the catalogues. ([#960](https://github.com/UltiKits/UltiTools-Reborn/pull/960), [#998](https://github.com/UltiKits/UltiTools-Reborn/pull/998), [#1002](https://github.com/UltiKits/UltiTools-Reborn/pull/1002))

- Legacy `lang/` files are not imported. If `lang/` folders remain in the framework's data folder or a module's configuration folder, UltiTools logs one notice at start-up listing them; it does not change or delete them. ([#1000](https://github.com/UltiKits/UltiTools-Reborn/pull/1000))
- The framework's own replies and console lines come from its catalogue. Operators can change them with override files, and `/ul reload` re-reads those files. ([#988](https://github.com/UltiKits/UltiTools-Reborn/pull/988))
- A standalone Paper plugin connected through the External Plugin API can ship its own `messages/<locale>.yml` catalogues. See [External plugin messages](/guide/advanced/external-plugin-api#external-plugin-messages). ([#1006](https://github.com/UltiKits/UltiTools-Reborn/pull/1006))

See [Messages and Languages](/guide/essentials/messages) and [Legacy Text Migration](/guide/essentials/i18n).

## Configuration

As of v7.0.0, translations for `@ConfigEntry` comment keys come from the module's `messages/<locale>.yml` catalogues. `/ul reload` reloads configuration and message overrides, not classes. A changed JAR takes effect only after a full server restart. See [Config File](/guide/essentials/config-file).

`UltiToolsPlugin#saveConfig(path, type)` throws `IllegalStateException` naming the module and path when no configuration entity is registered for that path; 6.x threw `NullPointerException`. In that case it writes no file. A registered entity of the wrong type causes `ClassCastException` naming the module, path, requested type and registered type. Register the entity before saving, or check that `getConfig(path, type)` returns a value. Do not catch `IllegalStateException` to detect a missing registration: `saveConfig` throws the same type when it is called off the server thread. ([#1017](https://github.com/UltiKits/UltiTools-Reborn/pull/1017))

## Data and Stored Items

As of v7.0.0, `ItemStackUtils` writes item arrays using Paper's item-byte format encoded as Base64. It still reads the old Bukkit object-stream format written by 6.x `ItemStackUtils`, but 6.x readers do not understand the new format. See [Items and Item Storage](/guide/essentials/items). ([#949](https://github.com/UltiKits/UltiTools-Reborn/pull/949))

`datasource.flushRate` sets the period of JSON flushes in seconds. A positive value sets the period, and a missing value or `0` uses 10 seconds. A negative value disables periodic flushing and logs one warning at start-up; 6.x ran a single background flush in that case. Normal shutdown still saves the JSON data. Periodic flushes follow wall-clock time instead of server ticks. Correct a negative value and restart the server. See [Operating JSON Storage](/guide/essentials/data-storage). ([#1016](https://github.com/UltiKits/UltiTools-Reborn/pull/1016))

`DataOperator#getLike` matches differently on MySQL, SQLite and JSON: SQL wildcards, case sensitivity and the text form of numbers depend on the backend. This behaviour is unchanged from 6.x and is now documented in [getLike](/guide/essentials/data-storage#getlike). For literal prefix, suffix or substring matching on every backend, use `WhereCondition` with `STARTSWITH`, `ENDSWITH` or `INCLUDE`. Never pass user input as the column name. ([#1014](https://github.com/UltiKits/UltiTools-Reborn/pull/1014))

## Scheduling

As of v7.0.0, modules inject `com.ultikits.ultitools.scheduling.Scheduler` with `@Autowired`. Each module instance owns its scheduler, and module tasks run on Paper's schedulers. Unloading the module, or a failed module load, cancels its pending and repeating tasks; a one-shot task that is already running may finish. See [Scheduler API](/guide/advanced/scheduled-tasks#scheduler-api). ([#950](https://github.com/UltiKits/UltiTools-Reborn/pull/950), [#963](https://github.com/UltiKits/UltiTools-Reborn/pull/963))

- Tasks submitted from `onUnregister()` or `@PreDestroy` are rejected with `RejectedExecutionException`, because the module's scheduler has already been retired. Do unload cleanup directly.
- Literal `@Scheduled(async = true)` periods use wall-clock time, 50 ms per configured tick, so a lagging server no longer stretches them. Config-bound async tasks still use a tick trigger.
- A negative literal `@Scheduled(delay = ...)` refuses the module load; 6.x treated it as zero. Use `delay = 0` for no initial wait.
- A one-shot task submitted with `run`, `runLater` or `execute` that throws logs exactly one WARNING with the owner's name and the original exception, and its handle ends `FAILED`. A failing `supply` reports through its future.

## Screens and Dialogs

As of v7.0.0, modules show screens through an injected `UiService`. It opens notices, confirmations, choices and forms as Paper dialogs, and chest grids as inventory screens. `DeclarativeGui` is rebuilt on it: the constructor takes the module's `UiService` and `Scheduler`, and the class no longer inherits obliviate's `Gui`. See [UI: Intents and Sessions](/guide/advanced/ui-service) and [Declarative GUI](/guide/advanced/declarative-gui). ([#948](https://github.com/UltiKits/UltiTools-Reborn/pull/948), [#953](https://github.com/UltiKits/UltiTools-Reborn/pull/953), [#968](https://github.com/UltiKits/UltiTools-Reborn/pull/968), [#969](https://github.com/UltiKits/UltiTools-Reborn/pull/969), [#975](https://github.com/UltiKits/UltiTools-Reborn/pull/975))

- A screen that the game interrupts, for example by the player's death, a world change or another inventory opening, ends with the new close reason `CloseReason.INTERRUPTED`.
- At server stop, storage-backed chest screens of all modules share one wait of about 10 seconds to save.

## Start-up and Bootstrap Content

As of v7.0.0, Paper runs the framework bootstrap before worlds load, while IoC and normal enable hooks run during plugin enable. An optional module bootstrap hook can declare custom enchantments, item and enchantment tags, and data packs bundled in the module JAR. These bootstrap channels rely on experimental Paper APIs. If a declared data pack contains world-generation data, the entire module is refused. See [Start-up Phases](/guide/advanced/startup-phases#bootstrap-content). ([#951](https://github.com/UltiKits/UltiTools-Reborn/pull/951), [#989](https://github.com/UltiKits/UltiTools-Reborn/pull/989))

## Module Changes and the Panel

As of v7.0.0, `/upm install`, `/upm update` and `/upm uninstall` queue changes until the next restart instead of changing running modules. Review them with `/upm pending` and undo an eligible entry with `/upm revoke <module>`. An uninstall no longer stops the running module; restart the server to remove it. A new install is refused before downloading if its target filename already exists in the modules folder. ([#990](https://github.com/UltiKits/UltiTools-Reborn/pull/990))

On a server connected to UltiCloud, the server owner can view pending changes in the panel and revoke eligible entries individually. See [Pending module changes](/guide/advanced/panel-integration#pending-module-changes). ([#996](https://github.com/UltiKits/UltiTools-Reborn/pull/996))

## Other Changes

- AOP proxies are defined through `MethodHandles.Lookup`, so creating one no longer prints the `sun.misc.Unsafe` warning on Java 25. A `sealed` bean class with AOP annotations is now refused in the same way as a `final` class. ([#933](https://github.com/UltiKits/UltiTools-Reborn/pull/933))

## Removed Public APIs

As of v7.0.0, several 6.x public APIs are removed, including legacy command, text and GUI APIs, the item and sound compatibility layer, and the toast and hologram helpers. `NotificationService` now uses `Text`, Adventure types and `Duration`, and its methods no longer return `boolean`. See the [upgrade guide](/guide/advanced/upgrading-to-7#removed-public-apis) and the framework's [compatibility policy and its 7.0.0 sections][compatibility policy]. ([#936](https://github.com/UltiKits/UltiTools-Reborn/pull/936), [#962](https://github.com/UltiKits/UltiTools-Reborn/pull/962), [#970](https://github.com/UltiKits/UltiTools-Reborn/pull/970), [#979](https://github.com/UltiKits/UltiTools-Reborn/pull/979))

- The framework no longer bundles XSeries, obliviate-invs or UniversalScheduler. A module that used them must package them itself or use Paper APIs.
- `ChatCallbackManager` and its hidden `/ultitools_callback` command are removed; use Adventure's `ClickEvent.callback`. ([#947](https://github.com/UltiKits/UltiTools-Reborn/pull/947))
- The class-name filter audit and seven `SecurityPolicy` and `ClassLoaderUtils` methods that had no effect since 6.3.0 are removed. Module JAR structure and size checks remain. ([#938](https://github.com/UltiKits/UltiTools-Reborn/pull/938))

## Known Limitations

- Restart the server after changing JARs. Server `/reload`, plugin-manager hot reload and re-enabling UltiTools without a restart are not supported.
- A stop or crash while worlds are loading can leave a pending module update unconfirmed; the next start then restores the previous JAR. Let start-up finish before stopping the server.
- Chest screens show display copies of items. Another plugin that clears the cancellation of their click or drag events can let vanilla move those copies and duplicate items.

The complete list of 7.0 limitations is in [COMPATIBILITY.md][compatibility policy].

Module authors and external plugin authors can start with [Upgrading from 6.x to 7.0](/guide/advanced/upgrading-to-7). Migrate and rebuild as described in the guide before testing on the new Paper baseline.
