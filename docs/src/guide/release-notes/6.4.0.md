# UltiTools-API 6.4.0 Release Notes (Draft)

::: info As of v6.4.0 (unreleased draft)
These notes describe the compatibility target and linked implementation work, not a released build or completed real-server acceptance.
:::

## Older-server compatibility

As of v6.4.0, UltiKits, UltiLogin, UltiMail, UltiRemoteBag and UltiTrade target Paper 1.19.2 build 163 or later. On Minecraft below 1.21, these five modules require UltiTools 6.4.0 or later; pairing them with an older framework must produce a clear upgrade refusal. On Minecraft 1.21 or later, this requirement leaves their 6.3.x framework compatibility intact. Install the corresponding module updates as well as the framework; framework adaptation alone does not provide the module-side fallbacks below.

The framework adapts `InventoryView`'s interface/class invocation difference at module load with one generic rule and no operator switch ([#806](https://github.com/UltiKits/UltiTools-Reborn/pull/806), [#809](https://github.com/UltiKits/UltiTools-Reborn/pull/809)). Each unresolved server-API reference produces a startup `WARNING` while loading continues. A skipped bean's consequence warning names the missing server class and lost handlers ([#810](https://github.com/UltiKits/UltiTools-Reborn/pull/810)). This does not substitute missing capabilities, rename events or isolate handlers within a single class. Module authors should use the [separate optional-listener pattern](/guide/advanced/older-servers).

## Module behavior and degradation

As of v6.4.0, the following cases distinguish binary adaptation from module-chosen fallback and unavailable capabilities:

| API difference | Module behavior in the 6.4.0 target |
| --- | --- |
| `InventoryView` is a class on Paper 1.19.2–1.20.6, an interface from 1.21 | The generic invocation-kind rule repairs the binary mismatch for the five modules; it does not add absent methods. |
| `InventoryView.setTitle(String)` is absent on 1.19.2–1.19.3 | UltiTrade redraws contents but does not refresh an already-open title until the window is reopened; no framework close/reopen shim is added ([UltiTrade #92](https://github.com/UltiKits/UltiTrade/pull/92)). |
| `OfflinePlayer.getLocation()` is absent on measured versions 1.19.2–1.20.1 | When a cancelled trade cannot use the offline partner's location, UltiTrade returns that stake to the original initiator, immediately if online or stored for claim on next login if offline; it never invents a world-spawn destination ([UltiTrade #92](https://github.com/UltiKits/UltiTrade/pull/92)). API availability on 1.20.2–1.20.3 was not measured. |
| The modern `org.bukkit.event.entity.EntityMountEvent` is absent on older servers | UltiLogin selects the real legacy `org.spigotmc.event.entity.EntityMountEvent` reflectively when the modern class is absent, preserving the core protections instead of relying on framework event renaming ([UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85)). |
| `PlayerPickItemEvent` and `PlayerOpenSignEvent` are absent on measured Paper 1.19.2–1.19.4 | UltiLogin probes them independently; without an equivalent event, the respective pick-item or sign-editor-open protection is unavailable and named in a startup warning. Other listeners remain registered; sign-change submission protection is not sign-editor-open protection ([UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85)). Both classes are present in the measured 1.20.1 API. |
| `PlayerSwapWithEquipmentSlotEvent` is absent on measured Paper versions through 1.21.4 | The dedicated equipment-swap protection is unavailable and warned about, without losing the retained Paper protections. The event is present in measured 1.21.11; 1.21.5–1.21.10 were not measured. Existing core interaction protection remains; off-hand swap is not an equivalent equipment-slot event ([UltiLogin #84](https://github.com/UltiKits/UltiLogin/pull/84)). |

### Paper 1.20.4 mount-event boundary

As of v6.4.0, the mount fallback distinguishes Paper 1.20.4 builds: the measurement behind [UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85) identifies builds 319–385 as legacy-event-only, while builds 386–499 contain both class names but fire only the modern Bukkit event. Register only the selected listener, never both. On 1.20.6 the legacy class is absent. The build-386 distinction is not a claim that the framework rewrites event names, nor a substitute for the module's pending native-action UAT.

## Draft status

As of v6.4.0, the linked PRs are implementation evidence, not a declaration that the full compatibility matrix has passed. Framework and module reviews, real-server acceptance and release authorization remain separate from these documentation notes. The historical [6.3.0 release notes](/guide/release-notes/6.3.0) continue to describe that release's limitations.
