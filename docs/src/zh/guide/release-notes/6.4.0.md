# UltiTools-API 6.4.0 更新说明（草稿）

::: info 自 v6.4.0 起（未发布草稿）
本说明描述兼容性目标及关联实现工作，不代表已发布构建或已完成真机验收。
:::

## 旧版服务端兼容性

自 v6.4.0 起，UltiKits、UltiLogin、UltiMail、UltiRemoteBag 和 UltiTrade 以 Paper 1.19.2 build 163 及以上版本为目标。在 Minecraft 1.21 以下，这五个模块要求 UltiTools 6.4.0 或以上版本；搭配旧框架时应明确提示升级并拒绝启动。在 Minecraft 1.21 及以上，此要求保留它们对 6.3.x 框架的兼容性。需要同时安装对应模块更新和框架，单靠框架适配不会提供下列模块侧回退行为。

框架在模块加载时使用一条通用规则适配 `InventoryView` 的接口与类调用差异，无服主开关（[#806](https://github.com/UltiKits/UltiTools-Reborn/pull/806)、[#809](https://github.com/UltiKits/UltiTools-Reborn/pull/809)）。只有模块自有扫描包内的类中无法解析的服务端 API 引用，才会逐条产生启动 `WARNING`；随模块打包的第三方库则按顶级包各输出一条 `INFO` 汇总。两种情况下加载都继续。bean 被跳过时，后果警告会列出缺失的服务端类和丢失的处理器（[#810](https://github.com/UltiKits/UltiTools-Reborn/pull/810)）。框架不会替代缺失能力、重命名事件或在同一个类内隔离处理器。模块作者应采用[独立可选监听器模式](/zh/guide/advanced/older-servers)。

## 模块行为与降级

自 v6.4.0 起，下列情况区分了二进制适配、模块选择的回退行为以及不可用的能力：

| API 差异 | 6.4.0 目标中的模块行为 |
| --- | --- |
| `InventoryView` 在 Paper 1.19.2–1.20.6 是类，从 1.21 起是接口 | 通用调用种类规则为五个模块修复二进制不匹配，但不会添加缺失方法。 |
| 1.19.2–1.19.3 缺少 `InventoryView.setTitle(String)` | UltiTrade 仍重绘内容，但已打开窗口的标题要等重新打开后才更新；框架不增加关闭再打开窗口的替代实现（[UltiTrade #92](https://github.com/UltiKits/UltiTrade/pull/92)）。 |
| 已测版本 1.19.2–1.20.1 缺少 `OfflinePlayer.getLocation()` | 取消交易时若无法使用离线对方的位置，UltiTrade 将其押注返还原交易发起者；发起者在线则立即交付，离线则存储至下次登录领取，绝不虚构世界出生点作为目的地（[UltiTrade #92](https://github.com/UltiKits/UltiTrade/pull/92)）。1.20.2–1.20.3 的 API 可用性未测量。 |
| 旧服务端缺少现代 `org.bukkit.event.entity.EntityMountEvent` | UltiLogin 在现代类不存在时反射选择真正的旧版 `org.spigotmc.event.entity.EntityMountEvent`，保留核心保护，不依赖框架重命名事件（[UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85)）。 |
| 已测 Paper 1.19.2–1.19.4 缺少 `PlayerPickItemEvent` 和 `PlayerOpenSignEvent` | UltiLogin 分别探测这两个事件；没有等价事件时，对应的选取物品或打开告示牌编辑器保护不可用，并有点名启动警告。其余监听器继续注册；提交告示牌修改保护不等于打开编辑器保护（[UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85)）。已测 1.20.1 API 中两个类均存在。 |
| 已测 Paper 版本直至 1.21.4 缺少 `PlayerSwapWithEquipmentSlotEvent` | 专用装备槽交换保护不可用并输出警告，但不会丢失保留的 Paper 保护。已测 1.21.11 中存在该事件；1.21.5–1.21.10 未测量。既有核心交互保护仍然存在，副手交换不等于装备槽交换事件（[UltiLogin #84](https://github.com/UltiKits/UltiLogin/pull/84)）。 |

### Paper 1.20.4 骑乘事件边界

自 v6.4.0 起，骑乘回退需要区分 Paper 1.20.4 构建：[UltiLogin #85](https://github.com/UltiKits/UltiLogin/pull/85) 所依据的测量表明，build 319–385 只有旧版事件，build 386–499 同时包含两个类名，但只触发现代 Bukkit 事件。只注册选中的监听器，不同时注册两者。1.20.6 中旧版类已不存在。build 386 的区别不表示框架会重写事件名，也不能替代模块尚待执行的原生操作 UAT。
