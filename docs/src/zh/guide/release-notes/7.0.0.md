# UltiTools-API 7.0.0 更新说明

7.0.0 是包含破坏性变更的版本。框架的目标环境改为 Paper 26.3（build 258）和 Java 25，只接受声明整数 `api-version` 不低于 `700` 的模块，并删除了许多 6.x 公开 API。为 6.x 构建的模块 JAR 不能在 7.0 上加载：请迁移每个模块的源码，针对 7.0 重新构建，再安装重新构建的 JAR。请从[从 6.x 升级到 7.0](/zh/guide/advanced/upgrading-to-7)开始。

7.0.0 用基于 Paper 和 Adventure 的实现替换了命令、文本、调度、物品和界面系统，新增了用于自定义内容的引导阶段，并把模块的安装、更新和卸载排队到下次重启时生效。7.0.0 是新的公开 API 基线，不与 6.x 做兼容性比较。

面向模块作者的完整清单见 [COMPATIBILITY.md][compatibility policy]，发布页见 [GitHub 上的 v7.0.0](https://github.com/UltiKits/UltiTools-Reborn/releases/tag/v7.0.0)。

::: warning 6.x 模块 JAR 无法加载
UltiTools 7.0 在启动时拒绝为 6.x 构建的模块 JAR，只修改其 `api-version` 不能让它兼容。请为每个模块安装 7.0 版本，并先备份服务器。
:::

## 升级前准备

- 备份旧的框架和模块 JAR、配置、世界和模块数据。7.0 写入的物品 6.x 无法读取，也不支持原地降级；要回到 6.x，请恢复备份。
- 安装 7.0 之前，让每个尚未确认的 6.x `/upm update` 先在 6.x 上完成一次确认启动。
- 安装 Java 25 和 Paper 26.3 build 258。启动时 Paper 会解析框架的运行时库，因此服务器需要能访问 Maven Central，或访问 Paper 环境变量 `PAPER_DEFAULT_CENTRAL_REPOSITORY` 指定的镜像，除非这些库已有缓存。
- 为正在使用的每个模块准备 7.0 版本。旧 `lang/` 文件里的服主修改不会被带过来；请按[消息与语言](/zh/guide/essentials/messages)的说明移到消息覆盖文件中。

完整步骤见[升级前准备](/zh/guide/advanced/upgrading-to-7#before-upgrade)。

## 运行环境

自 v7.0.0 起，目标环境为 Paper 26.3（build 258）和 Java 25。不支持更早的 Paper 版本或普通 Spigot；6.x 的历史兼容说明见[旧服务器](/zh/guide/advanced/older-servers)。（[#928](https://github.com/UltiKits/UltiTools-Reborn/pull/928)）

框架 JAR 现在是 Paper 插件：它包含 `paper-plugin.yml`，不再包含 `plugin.yml`。模块 JAR 仍使用自己的 `plugin.yml`。Paper 无法下载某个运行时库时，可能只报告 `Error resolving libraries`；请检查服务器的网络访问和镜像。（[#951](https://github.com/UltiKits/UltiTools-Reborn/pull/951)）

## 模块准入

自 v7.0.0 起，模块 JAR 根目录的 `plugin.yml` 必须声明整数 `api-version`，取值范围为 `700` 至当前运行的框架 API 级别，含两端。6.x 模块须针对 7.0 和目标 Paper 版本重新构建；只改声明不能让旧 JAR 兼容。见[构建目标与模块准入](/zh/guide/advanced/upgrading-to-7#build-target)。

框架按原样加载通过准入的模块 JAR。6.x 的加载期字节码适配、服务端 API 探测以及启动和离线链接审计均已删除。（[#937](https://github.com/UltiKits/UltiTools-Reborn/pull/937)）

## 命令

自 v7.0.0 起，UltiTools 将注解命令编译成 Brigadier 命令树，通过 Paper 的命令生命周期事件注册。不再通过修改 Bukkit 的私有命令表来注册。6.x 接受的命令格式现在可能导致所在模块无法加载；见[命令执行器](/zh/guide/essentials/cmd-executor)及其中的[被拒绝的格式](/zh/guide/essentials/cmd-executor#被拒绝的格式)。（[#965](https://github.com/UltiKits/UltiTools-Reborn/pull/965)）

- 框架对命令的回复，例如用法、权限拒绝和冷却提示，按每个玩家自己的语言发送。（[#977](https://github.com/UltiKits/UltiTools-Reborn/pull/977)）
- `@AsyncCommand(processingMessageKey = ...)` 接受 `<namespace>:<path>` 形式的消息键。值无效时记录一条警告，并使用默认的处理中提示。
- 异步命令体在框架调度器上运行。卸载模块时，框架为该模块仍在运行的异步命令总共等待约 10 秒，不中断它们。

## 文本与多语言

自 v7.0.0 起，`Messages` 和 `messages/<locale>.yml` 消息目录是唯一的文本系统。每个玩家按自己的客户端语言收到文本，同时受服主语言设置约束。模块配置注释、命令描述和提示也来自消息目录。（[#960](https://github.com/UltiKits/UltiTools-Reborn/pull/960)、[#998](https://github.com/UltiKits/UltiTools-Reborn/pull/998)、[#1002](https://github.com/UltiKits/UltiTools-Reborn/pull/1002)）

- 旧 `lang/` 文件不会自动导入。如果框架数据目录或模块配置目录下仍有 `lang/` 文件夹，UltiTools 会在启动时记录一条列出它们的提示，不修改也不删除它们。（[#1000](https://github.com/UltiKits/UltiTools-Reborn/pull/1000)）
- 框架自己的回复和控制台文本来自它的消息目录。服主可以用覆盖文件修改它们，`/ul reload` 会重新读取这些文件。（[#988](https://github.com/UltiKits/UltiTools-Reborn/pull/988)）
- 通过外部插件 API 连接的独立 Paper 插件可以附带自己的 `messages/<locale>.yml` 消息目录。见[外部插件自己的消息文件](/zh/guide/advanced/external-plugin-api#external-plugin-messages)。（[#1006](https://github.com/UltiKits/UltiTools-Reborn/pull/1006)）

见[消息与语言](/zh/guide/essentials/messages)和[旧文本迁移](/zh/guide/essentials/i18n)。

## 配置

自 v7.0.0 起，`@ConfigEntry` 注释键对应的译文来自模块的 `messages/<locale>.yml` 消息目录。`/ul reload` 重载配置和消息覆盖文件，不重载类。更换 JAR 后须完整重启服务器才生效。见[配置文件](/zh/guide/essentials/config-file)。

该路径没有登记配置实体时，`UltiToolsPlugin#saveConfig(path, type)` 抛出指明模块和路径的 `IllegalStateException`；6.x 抛出的是 `NullPointerException`。这种情况下它不写任何文件。已登记实体的类型不符时抛出 `ClassCastException`，指明模块、路径、请求的类型和已登记的类型。请先登记实体再保存，或先检查 `getConfig(path, type)` 是否返回了值。不要用捕获 `IllegalStateException` 来判断是否已登记：在服务器线程以外调用时，`saveConfig` 抛出的也是这个类型。（[#1017](https://github.com/UltiKits/UltiTools-Reborn/pull/1017)）

## 数据与物品存储

自 v7.0.0 起，`ItemStackUtils` 用 Paper 的物品字节格式写入物品数组，再编码为 Base64。它仍能读取 6.x `ItemStackUtils` 写出的旧 Bukkit 对象流，但 6.x 的读取器不识别新格式。见[物品与物品存储](/zh/guide/essentials/items)。（[#949](https://github.com/UltiKits/UltiTools-Reborn/pull/949)）

`datasource.flushRate` 以秒为单位设置 JSON 周期落盘的间隔。正数即为间隔，未设置或为 `0` 时使用 10 秒。负数会关闭周期落盘，并在启动时记录一条警告；6.x 在这种情况下会执行一次后台落盘。正常停服仍会保存 JSON 数据。周期落盘按实际时间计时，不再按服务器 tick 计时。请把负数改正后重启服务器。见[数据储存](/zh/guide/essentials/data-storage)中的 JSON 存储运维说明。（[#1016](https://github.com/UltiKits/UltiTools-Reborn/pull/1016)）

`DataOperator#getLike` 在 MySQL、SQLite 和 JSON 上的匹配方式不同：SQL 通配符、大小写敏感性以及数字的文本形式都取决于存储后端。这一行为与 6.x 相同，现已写入 [getLike](/zh/guide/essentials/data-storage#getlike)。要在所有后端上按字面做前缀、后缀或子串匹配，请使用带 `STARTSWITH`、`ENDSWITH` 或 `INCLUDE` 的 `WhereCondition`。不要把用户输入当作列名传入。（[#1014](https://github.com/UltiKits/UltiTools-Reborn/pull/1014)）

## 调度

自 v7.0.0 起，模块通过 `@Autowired` 注入 `com.ultikits.ultitools.scheduling.Scheduler`。每个模块实例拥有自己的调度器，模块任务运行在 Paper 的调度器上。卸载模块或模块加载失败时，会取消它尚未执行的任务和重复任务；正在运行的一次性任务可能会执行完。见[调度器 API](/zh/guide/advanced/scheduled-tasks#调度器-api)。（[#950](https://github.com/UltiKits/UltiTools-Reborn/pull/950)、[#963](https://github.com/UltiKits/UltiTools-Reborn/pull/963)）

- 在 `onUnregister()` 或 `@PreDestroy` 中提交的任务会被 `RejectedExecutionException` 拒绝，因为模块的调度器此时已经停用。卸载清理请直接执行。
- 字面量 `@Scheduled(async = true)` 的周期按实际时间计算，每个配置的 tick 为 50 毫秒，服务器卡顿不再拉长这些周期。绑定到配置项的异步任务仍使用 tick 触发。
- 字面量 `@Scheduled(delay = ...)` 为负数时，模块加载被拒绝；6.x 把它当作 0。不需要初始等待时请写 `delay = 0`。
- 通过 `run`、`runLater` 或 `execute` 提交的一次性任务抛出异常时，恰好记录一条带拥有者名称和原始异常的 WARNING，其句柄以 `FAILED` 结束。`supply` 的异常通过它返回的 future 报告。

## 界面与对话框

自 v7.0.0 起，模块通过注入的 `UiService` 显示界面。它把通知、确认、选择和表单作为 Paper 对话框打开，把箱子网格作为物品栏界面打开。`DeclarativeGui` 基于它重建：构造器接收模块的 `UiService` 和 `Scheduler`，该类不再继承 obliviate 的 `Gui`。见[界面：意图与会话](/zh/guide/advanced/ui-service)和[声明式 GUI](/zh/guide/advanced/declarative-gui)。（[#948](https://github.com/UltiKits/UltiTools-Reborn/pull/948)、[#953](https://github.com/UltiKits/UltiTools-Reborn/pull/953)、[#968](https://github.com/UltiKits/UltiTools-Reborn/pull/968)、[#969](https://github.com/UltiKits/UltiTools-Reborn/pull/969)、[#975](https://github.com/UltiKits/UltiTools-Reborn/pull/975)）

- 被游戏打断的界面，例如玩家死亡、切换世界或打开另一个物品栏时，以新的关闭原因 `CloseReason.INTERRUPTED` 结束。
- 停服时，所有模块中由存储支持的箱子界面共用约 10 秒的保存等待时间。

## 启动阶段与引导期内容

自 v7.0.0 起，Paper 在加载世界前运行框架的引导阶段，IoC 和常规启用钩子仍在插件启用阶段运行。模块可通过可选的引导钩子声明自定义附魔、物品和附魔标签，以及模块 JAR 内附带的数据包。这些引导渠道依赖 Paper 的实验性 API；如果声明的数据包包含世界生成数据，整个模块都不会加载。见[启动阶段](/zh/guide/advanced/startup-phases#bootstrap-content)。（[#951](https://github.com/UltiKits/UltiTools-Reborn/pull/951)、[#989](https://github.com/UltiKits/UltiTools-Reborn/pull/989)）

## 模块变更与面板

自 v7.0.0 起，`/upm install`、`/upm update` 和 `/upm uninstall` 把变更排队到下次重启，不再改动正在运行的模块。用 `/upm pending` 查看，用 `/upm revoke <module>` 撤销可撤销的条目。卸载不再立即停止正在运行的模块；要移除它请重启服务器。新安装的目标文件名已存在于模块目录时，安装会在下载前被拒绝。（[#990](https://github.com/UltiKits/UltiTools-Reborn/pull/990)）

服务器连接 UltiCloud 后，服务器所有者可以在面板查看待生效清单，并逐项撤销可撤销的变更。见[待生效的模块变更](/zh/guide/advanced/panel-integration#pending-module-changes)。（[#996](https://github.com/UltiKits/UltiTools-Reborn/pull/996)）

## 其他变更

- AOP 代理改为通过 `MethodHandles.Lookup` 定义，在 Java 25 上创建代理时不再打印 `sun.misc.Unsafe` 警告。带 AOP 注解的 `sealed` Bean 类现在与 `final` 类一样被拒绝。（[#933](https://github.com/UltiKits/UltiTools-Reborn/pull/933)）

## 已删除的公开 API

自 v7.0.0 起，部分 6.x 公开 API 已移除，包括旧命令、文本和 GUI API、物品与音效兼容层、进度弹窗和悬浮字工具。`NotificationService` 改用 `Text`、Adventure 类型和 `Duration`，方法不再返回 `boolean`。见[升级指南](/zh/guide/advanced/upgrading-to-7#removed-public-apis)与框架的[兼容性政策及移除说明][compatibility policy]。（[#936](https://github.com/UltiKits/UltiTools-Reborn/pull/936)、[#962](https://github.com/UltiKits/UltiTools-Reborn/pull/962)、[#970](https://github.com/UltiKits/UltiTools-Reborn/pull/970)、[#979](https://github.com/UltiKits/UltiTools-Reborn/pull/979)）

- 框架不再附带 XSeries、obliviate-invs 和 UniversalScheduler。用到它们的模块须自行打包，或改用 Paper API。
- `ChatCallbackManager` 及其隐藏命令 `/ultitools_callback` 已删除；请改用 Adventure 的 `ClickEvent.callback`。（[#947](https://github.com/UltiKits/UltiTools-Reborn/pull/947)）
- 类名过滤审计，以及自 6.3.0 起已不起作用的七个 `SecurityPolicy` 和 `ClassLoaderUtils` 方法已删除。模块 JAR 的结构和大小检查保留。（[#938](https://github.com/UltiKits/UltiTools-Reborn/pull/938)）

## 已知限制

- 更换 JAR 后请重启服务器。不支持服务器 `/reload`、插件管理器热重载，也不支持不重启就重新启用 UltiTools。
- 在加载世界期间停服或崩溃，可能使待生效的模块更新得不到确认，下次启动会恢复之前的 JAR。请等启动完成后再停服。
- 箱子界面显示的是物品的展示副本。其他插件如果清除了这些点击或拖拽事件的取消状态，原版可能移动展示副本并复制物品。

7.0 已知限制的完整清单见 [COMPATIBILITY.md][compatibility policy]。

## 升级入口

模块作者和外部插件作者请阅读[从 6.x 升级到 7.0](/zh/guide/advanced/upgrading-to-7)。在新的 Paper 环境中测试前，请按指南完成迁移并重新构建。
