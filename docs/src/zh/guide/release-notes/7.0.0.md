# UltiTools-API 7.0.0 更新说明

7.0.0 尚未发布。本页将随开发进度更新。

## 运行环境

自 v7.0.0 起，目标环境为 Paper 26.3（build 258）和 Java 25。不支持更早的 Paper 版本或普通 Spigot；6.x 的历史兼容说明见[旧服务器](/zh/guide/advanced/older-servers)。

## 模块准入

自 v7.0.0 起，模块 JAR 根目录的 `plugin.yml` 必须声明整数 `api-version`，取值范围为 `700` 至当前运行的框架 API 级别，含两端。6.x 模块须针对 7.0 和目标 Paper 版本重新构建；只改声明不能让旧 JAR 兼容。见[模块版本规范](/zh/guide/advanced/module-versioning#modules-6x-to-7)。

## 命令

自 v7.0.0 起，UltiTools 将注解命令编译成 Brigadier 命令树，通过 Paper 的命令生命周期事件注册。不再通过修改 Bukkit 的私有命令表来注册。见[命令执行器](/zh/guide/essentials/cmd-executor)。

## 文本与多语言

自 v7.0.0 起，`Messages` 和 `messages/<locale>.yml` 消息目录是唯一的文本系统。旧 `lang/` 文件不会自动导入；见[消息与语言](/zh/guide/essentials/messages)和[旧文本迁移](/zh/guide/essentials/i18n)。

## 配置

自 v7.0.0 起，`@ConfigEntry` 注释键对应的译文来自模块的 `messages/<locale>.yml` 消息目录。`/ul reload` 重载配置，不重载类；更换 JAR 后须完整重启服务器。见[配置文件](/zh/guide/essentials/config-file)。

## 数据与物品存储

自 v7.0.0 起，`ItemStackUtils` 用 Paper 的物品字节格式写入物品数组，再编码为 Base64。它仍能读取 6.x `ItemStackUtils` 写出的旧 Bukkit 对象流，但 6.x 的读取器不识别新格式。见[物品与物品存储](/zh/guide/essentials/items)。

## 启动阶段与引导期内容

自 v7.0.0 起，Paper 在加载世界前运行框架的引导阶段，IoC 和常规启用钩子仍在插件启用阶段运行。模块可通过可选的引导钩子声明自定义附魔、物品和附魔标签，以及模块 JAR 内附带的数据包。见[启动阶段](/zh/guide/advanced/startup-phases#bootstrap-content)。

## 面板与 UltiCloud

自 v7.0.0 起，模块安装、更新和卸载排队到下次重启时生效。服务器连接 UltiCloud 后，服务器所有者可以在面板查看待生效清单，并逐项撤销可撤销的变更。见[面板集成](/zh/guide/advanced/panel-integration)。

## 已删除的公开 API

自 v7.0.0 起，部分 6.x 公开 API 已移除，包括旧命令、文本和 GUI API；见[升级指南](/zh/guide/advanced/upgrading-to-7)与框架的[兼容性政策及移除说明][compatibility policy]。

## 升级入口

模块作者和外部插件作者请阅读[从 6.x 升级到 7.0](/zh/guide/advanced/upgrading-to-7)。在新的 Paper 环境中测试前，请先完成检查清单。

[compatibility policy]: https://github.com/UltiKits/UltiTools-Reborn/blob/main/COMPATIBILITY.md
