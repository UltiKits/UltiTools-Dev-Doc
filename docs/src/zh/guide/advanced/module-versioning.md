# 模块版本规范

这一页讲的是**你的模块**自己的版本号。它不是 `UltiTools-API` 的版本号规则——
框架走的是另一套契约，原因见[为什么模块和框架不一样](#为什么模块和框架不一样)。

## 判据只有一个问题

> **服主换上新 JAR 之后，需不需要动手？**

下面所有规则都是从这一句推出来的。

| | 含义 | 服主要做什么 |
|---|---|---|
| **MAJOR** | 升级需要人工介入 | 手改配置 · 迁移数据 · 重新适应被删除或改名的命令、权限节点 |
| **MINOR** | 新增功能，向后兼容 | 直接换 JAR。旧配置继续工作；新功能可能需要在配置里开 |
| **PATCH** | 修复与内部改动，含纯 CI／构建配置改动 | 直接换 JAR，什么都不用做 |

判据写成「要做多少事」而不是「改动有多大」，是因为两者并不相关。把模块内部
整个重写，只要配置文件和命令没变，那就是 PATCH；改一个权限节点的名字只是一行
diff，却是 MAJOR——因为每一台授予过那个节点的服务器，现在都悄悄少了一项权限。

### bump 之前的检查清单

- [ ] 服主的配置文件需要手改吗？→ **MAJOR**
- [ ] 已有的数据需要迁移吗？→ **MAJOR**
- [ ] 有命令或权限节点被删除或改名吗？→ **MAJOR**
- [ ] 三个都否，但有新功能？→ **MINOR**
- [ ] 三个都否，也没新功能？→ **PATCH**

## 为什么模块和框架不一样

`UltiTools-API` 的 [`COMPATIBILITY.md`](https://github.com/UltiKits/UltiTools-Reborn/blob/alpha/COMPATIBILITY.md) 写着：它的版本号是**产品阶段信号，不是严格
的 semver 契约**——框架的 MINOR 版本**可以移除** API。

这看起来和上面的规则自相矛盾。它不矛盾，而且在有人试图「统一」两者之前，值得先
把差别搞清楚。

框架有**机器消费者**：Maven 要解析它的版本，已编译的下游插件在运行时链接它。一个
会被机器采信的版本号，必须回答机器的问题。

模块**没有任何机器消费者**：没有模块发布到 Maven 仓库，模块之间也不互相依赖。模块
版本号唯一的读者，是一个正在判断「换这个 JAR 安不安全」的服主。

**同样的版本号语法，不同的契约，因为它们面向不同的读者。**

## 对 `UltiTools-API` 的 pin 是地板，不是新鲜度指标

模块把框架声明为 `provided`：

```xml
<dependency>
    <groupId>com.ultikits</groupId>
    <artifactId>UltiTools-API</artifactId>
    <version>${ultitools.version}</version>
    <scope>provided</scope>
</dependency>
```

`provided` 的意思是：模块**编译**时用 pin 的那个版本，**运行**时用服务器上实际
装的框架。这个不对称正是关键：

- 编译against**旧** API → 可以证明模块只用了那个版本就有的东西 → 它能跑在该版本
  **以及之后所有**服务器上。
- 编译against**新** API → 可能用到服务器的框架没有的方法 → 启动时 `NoSuchMethodError`。

所以 pin 落后于最新正式版**是正常状态，不是等着被修的漂移**。它声明的是「本模块
要求框架至少是 X」，和模块 `plugin.yml` 里的 `api-version` 说的是同一件事。

**只在模块真的开始用新 API 时，才 bump 这个 pin。**

::: warning 反方向的风险
框架的 MINOR 版本**可以移除** API（还是那句，见 `COMPATIBILITY.md`）。一个 pin 在
旧版本、且用了已被移除类型的模块，在装了新框架的服务器上会 `NoClassDefFoundError`。

对付它的办法是**跟进废弃通告**——读移除清单，在移除真正发生之前迁移完。把 pin 调到
最新**一点也不能缓解它**：pin 决定的是你编译against什么，而那个类在运行时已经没了，
调不调都一样。
:::

## 目前各模块的状态

大部分模块还停在 `1.0.0`，因为它们还没有过需要做这个判断的发布。有两个在这一页
存在之前就各自做了判断，而且结论相反——一个用 MINOR 表示 bug 修复，另一个用 MAJOR
表示新功能，都对不上上面那张表。它们会按模块逐个校正口径，而不是回溯改号：已经
发布出去的版本号，服主可能已经记在什么地方了。
